# 服务器连接问题排查指南

## 错误说明

**错误信息：** `ERR_CONNECTION_REFUSED`  
**含义：** 客户端无法连接到服务器，连接被拒绝。

---

## 问题诊断步骤

### 步骤1：检查服务器是否正在运行

#### 方法1：查看服务器控制台输出

启动服务器后，应该看到类似以下输出：

```
========================================
✅ 单个角色数据服务器运行在 http://localhost:3000
数据目录: ...
角色数据文件: ...
道具数据文件: ...
========================================

API端点（端口3000）：
  GET  /api/characters/:name        - 获取单个角色数据
  PUT  /api/characters/:name        - 保存角色数据
  GET  /api/inventory               - 获取道具列表
  PUT  /api/inventory               - 保存道具列表
  GET  /api/admin/data              - 查看所有数据（调试）
  POST /api/admin/reset              - 重置所有数据（测试）
========================================

========================================
✅ 所有角色数据服务器运行在 http://localhost:3001
========================================

API端点（端口3001）：
  GET  /api/characters              - 获取所有角色数据
========================================
```

**重要：** 必须看到**两条**成功消息：
- ✅ 单个角色数据服务器运行在 http://localhost:3000
- ✅ 所有角色数据服务器运行在 http://localhost:3001

如果只看到一条，说明另一个端口启动失败了。

#### 方法2：检查端口占用情况

**Windows：**
```bash
netstat -ano | findstr ":3000"
netstat -ano | findstr ":3001"
```

**Mac/Linux：**
```bash
lsof -i :3000
lsof -i :3001
```

如果端口没有被占用，说明服务器没有启动。

---

### 步骤2：启动服务器

如果服务器没有运行，需要启动它：

```bash
cd BattleGame
node server.js
```

**注意：** 确保在 `BattleGame` 目录下运行，因为服务器需要访问 `data` 目录。

---

### 步骤3：检查端口占用错误

如果启动服务器时看到端口占用错误：

```
❌ 错误: 端口 3001 已被占用！
```

**解决方案：**

#### Windows系统

1. **查找占用端口的进程：**
   ```bash
   netstat -ano | findstr :3001
   ```
   会显示类似：
   ```
   TCP    0.0.0.0:3001    0.0.0.0:0    LISTENING    12345
   ```

2. **关闭进程：**
   ```bash
   taskkill /PID 12345 /F
   ```

#### Mac/Linux系统

1. **查找占用端口的进程：**
   ```bash
   lsof -i :3001
   ```

2. **关闭进程：**
   ```bash
   kill -9 <PID>
   ```

---

### 步骤4：检查服务器代码错误

如果服务器启动时出现其他错误（不是端口占用），检查：

1. **Node.js版本：** 确保安装了Node.js（建议v14+）
   ```bash
   node --version
   ```

2. **依赖包：** 确保安装了所有依赖
   ```bash
   cd BattleGame
   npm install
   ```

3. **文件权限：** 确保有权限创建 `data` 目录和文件

---

### 步骤5：测试服务器连接

#### 方法1：使用浏览器测试

打开浏览器，访问：
- `http://localhost:3000/api/admin/data` - 应该返回JSON数据
- `http://localhost:3001/api/characters` - 应该返回JSON数据（可能需要Authorization header）

#### 方法2：使用curl测试

**Windows（PowerShell）：**
```powershell
# 测试端口3000
Invoke-WebRequest -Uri "http://localhost:3000/api/admin/data" | Select-Object -ExpandProperty Content

# 测试端口3001（需要Authorization）
$headers = @{ "Authorization" = "Bearer 1" }
Invoke-WebRequest -Uri "http://localhost:3001/api/characters" -Headers $headers | Select-Object -ExpandProperty Content
```

**Mac/Linux：**
```bash
# 测试端口3000
curl http://localhost:3000/api/admin/data

# 测试端口3001
curl -H "Authorization: Bearer 1" http://localhost:3001/api/characters
```

## 常见问题

### Q1: 为什么只看到端口3000启动成功，3001失败了？

**可能原因：**
1. 端口3001被其他程序占用
2. 服务器代码有错误（已修复）

**解决方案：**
- 检查端口占用情况
- 查看服务器控制台的错误信息
- 确保两个服务器实例都成功启动

### Q2: 服务器启动后，客户端仍然连接失败？

**检查：**
1. 服务器是否真的在运行（检查控制台输出）
2. 防火墙是否阻止了连接
3. 客户端配置的URL是否正确

### Q3: 如何确认两个端口都成功启动？

**方法：**
1. 查看服务器控制台，应该看到两条成功消息
2. 使用 `netstat` 或 `lsof` 检查两个端口都在监听
3. 使用浏览器或curl测试两个端口的API

## 快速解决方案

### 如果服务器没有运行：

```bash
# 1. 进入项目目录
cd BattleGame

# 2. 启动服务器
node server.js

# 3. 确认看到两条成功消息：
#    ✅ 单个角色数据服务器运行在 http://localhost:3000
#    ✅ 所有角色数据服务器运行在 http://localhost:3001
```

### 如果端口被占用：

**Windows：**
```bash
# 关闭占用3000端口的进程
for /f "tokens=5" %a in ('netstat -ano ^| findstr :3000') do taskkill /PID %a /F

# 关闭占用3001端口的进程
for /f "tokens=5" %a in ('netstat -ano ^| findstr :3001') do taskkill /PID %a /F
```

**Mac/Linux：**
```bash
# 关闭占用端口的进程
lsof -ti:3000 | xargs kill -9
lsof -ti:3001 | xargs kill -9
```

---

## 总结

**ERR_CONNECTION_REFUSED** 错误通常意味着：

1. ✅ **服务器没有启动** - 启动服务器
2. ✅ **端口被占用** - 关闭占用端口的进程
3. ✅ **服务器启动失败** - 检查错误信息并修复
4. ✅ **防火墙阻止** - 检查防火墙设置

**最重要：** 确保看到两条服务器启动成功的消息！
