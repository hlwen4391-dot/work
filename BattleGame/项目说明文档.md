# 项目说明文档

本文档从**架构、逻辑、功能板块、实现逻辑**等方面对项目进行说明，便于理解与后续扩展。

---

## 一、项目概述

本项目是一个基于 **Cocos Creator** 的**回合制/时间驱动战斗游戏**，包含：

- **客户端**：Cocos Creator 游戏（`BattleGame` 目录），运行在浏览器或原生平台。
- **服务端**：Node.js + Express（`server.js`），提供角色、道具、金币、技能等数据的持久化 API。
- **根目录**：存在部分与战斗相关的独立脚本（如 `BattleSystem.js`、`BuffSystem.js` 等），部分逻辑已迁移到 `BattleGame/assets/Scripts/system` 中，与 Cocos 组件协同工作。

**核心玩法**：英雄 vs 怪物双阵营对战，按速度排序行动，支持普通攻击、多种技能、Buff/DeBuff、暴击/闪避/护盾等；战斗可记录并支持回放；角色有等级/经验、背包、技能学习；商城购买道具与金币消耗。

---

## 二、整体架构

### 2.1 目录结构（客户端）

```
BattleGame/
├── assets/
│   ├── Scripts/           # 游戏脚本
│   │   ├── ecs/           # 组件与 UI（挂到节点上的 Cocos 组件）
│   │   ├── game/          # 场景控制器与配置（关卡、单位、道具、商城）
│   │   └── system/        # 系统逻辑（战斗、技能、Buff、数据适配、记录回放）
│   ├── Scenes/            # 场景资源
│   └── ...
├── data/                  # 本地/服务器持久化数据（JSON）
├── server.js              # 后端 API 服务
└── 项目说明文档.md        # 本文档
```

- **ecs**：与“实体”展示和交互相关的组件（血条、技能按钮、攻击移动、回放控制、人物查看、商城 UI 等）。
- **game**：场景入口、关卡/单位/道具/商城等**配置**与**场景控制器**（MainMenu、Select、Battle、Shop、CharacterView、GameOver 等）。
- **system**：与具体节点弱耦合的**系统**（战斗流程、技能/Buff/伤害计算、数据读写、战斗记录与回放）。

### 2.2 客户端–服务端关系

- **存储模式**：通过 `ServerConfig` 与各 **Adapter**（Character/Item/Skill/Coin）配置为 `local`、`server` 或 `hybrid`。
- **服务器**：`server.js` 提供 REST API，使用 JSON 文件存储角色、背包、金币、技能等；支持 Token 鉴权（如 Bearer）。
- **数据流**：  
  **UI/场景** → **Manager**（CharacterDataManager、ItemDataManager、SkillDataManager、CoinManager）→ **Adapter**（CharacterDataAdapter 等）→ **localStorage 或 HTTP 请求**。

## 三、功能板块

### 3.1 主菜单（MainMenu）

- **脚本**：`game/MainMenuScene.js`
- **职责**：主菜单 UI、初始化服务器配置、加载角色数据；提供入口：
  - **开始游戏** → 跳转选择场景（SelectScene）
  - **查看人物** → 跳转人物属性查看场景（CharacterViewScene）
  - **商城** → 跳转商城场景（ShopScene）
  - （可选）清除数据、添加道具/金币测试按钮

### 3.2 选择场景（SelectScene）

- **脚本**：`game/SelectScene.js`、`ecs/SelectSceneUI.js`
- **职责**：关卡/阵容选择、英雄与怪物配置；将选中的单位写入 `window.SelectedUnits`，供战斗场景使用。
- **流程**：选择阵容 → 点击开始战斗 → 加载战斗场景（BattleScene），BattleController 根据 `SelectedUnits` 创建/排布英雄与怪物节点。

### 3.3 战斗场景（BattleScene）

- **脚本**：`game/BattleController.js`（场景总控）、`system/BattleSystem.js`（战斗循环与行动队列）
- **职责**：
  - 根据 SelectScene 的选择或场景配置，实例化英雄/怪物 Prefab，挂载 StatsComponent、SkillComponent、TeamComponent、BuffComponent 等。
  - 使用 **BattleSystem** 驱动：每帧按**速度**将“待行动单位”加入**行动队列**；从队列取出一项，交给 **ActionSystem** 执行（选技能、选目标、技能/普攻、伤害结算、死亡判定）。
  - 支持**攻击动画**（AttackMover：近战移动+攻击+返回，远程仅播放攻击动画）、**大招 UI**（怒气满可释放，可暂停战斗循环）。
  - 可选**战斗记录**（BattleRecorder）：记录初始状态与事件（行动开始、技能释放、伤害、治疗、Buff、死亡等），供回放使用。

### 3.4 战斗回放

- **脚本**：`system/BattleRecorder.js`（记录）、`system/BattleReplayer.js`（回放逻辑）、`ecs/ReplayController.js`（回放 UI）
- **职责**：
  - **BattleRecorder**：在战斗过程中记录 `initialState`（单位序列化）、`events`（时间戳+类型+数据）。
  - **BattleReplayer**：按时间戳重放事件，通过 `unitMap` 将记录中的单位 ID 映射到当前场景单位节点，驱动伤害/治疗/死亡/Buff 等表现。
  - **ReplayController**：提供播放/暂停、停止、倍速、进度条等 UI，停止后可跳转 GameOver 等场景。

### 3.5 人物属性查看（CharacterViewScene）

- **脚本**：`game/CharacterViewScene.js`、`ecs/CharacterViewUI.js`
- **职责**：展示角色列表（头像）、选中角色的属性与技能、**道具栏**（背包）。道具栏从 ItemDataManager 拉取数据，按格子显示图标与数量；支持使用道具、Tooltip 等。  
- **数据**：角色数据来自 CharacterDataManager（等级、经验、属性），技能来自 SkillDataManager，背包来自 ItemDataManager（全局共享）。

### 3.6 商城（ShopScene）

- **脚本**：`game/ShopScene.js`、`ecs/ShopUI.js`、`game/ShopConfig.js`
- **职责**：展示商城商品列表（来自 ShopConfig），分页显示；购买时扣金币（CoinManager）、增加背包道具（ItemDataManager），并可对接服务器购买接口。

### 3.7 游戏结束（GameOverScene）

- **脚本**：`game/GameOverScene.js`、`game/GameOverSceneData.js`、`ecs/GameOverPanel.js`
- **职责**：根据胜负显示结果；可发放奖励（经验、金币）、保存角色数据，并提供再战/返回主菜单等按钮。

## 四、核心逻辑与实现

### 4.1 战斗流程（BattleSystem + ActionSystem）

1. **BattleSystem**（`system/BattleSystem.js`）  
   - 持有英雄/怪物数组引用，并写入 **TeamRef**（供技能/Buff 按阵营取目标）。
   - 每帧 `update(dt)`：若未结束且未暂停、且当前无正在处理的行动，则按**速度**对存活单位排序，将“该回合应行动”的单位加入 **actionQueue**。
   - 从队列取出一项 `{ unit, dt }`，设置 `isProcessingAction = true`，调用 **ActionSystem.performAction(unit, dt, callback)**；在 callback 里再次检查是否结束、否则 `_processNextAction()` 继续。

2. **ActionSystem**（`system/ActionSystem.js`）  
   - **performAction(entity, dt, callback)**：  
     - 更新 Buff（BuffSystem.update）、检查死亡（DeathSystem）、眩晕则本回合不行动。  
     - 更新技能冷却（SkillSystem.updateCooldowns）。  
     - 选技能：**SkillSystem.findAvailableSkill(entity)**（优先大招：怒气≥requireRage；其次非普攻且冷却好的技能；最后普攻）。  
     - 选目标：**pickRandomTarget(entity)**（按 TeamComponent 取敌方存活单位随机一个）。  
     - 若为大招：直接 **SkillSystem.useSkill**，callback 在大招 UI 结束后调用。  
     - 若有 **AttackMover**：执行 `attackTarget(target, onHit, onComplete)`；**onHit** 在受击动画中途触发伤害（SkillSystem.useSkill）；**onComplete** 再检查死亡并执行 callback。  
     - 若无 AttackMover：直接 useSkill 再 callback。

### 4.2 技能系统（SkillSystem + SkillConfig）

- **SkillConfig**（`system/SkillConfig.js`）：定义技能 ID、名称、冷却、伤害类型、目标类型（单体/己方群体/敌方群体）、怒气需求等。
- **SkillComponent**：挂在单位节点上，持有 `skills` 列表和 `cooldowns`。
- **SkillSystem**：  
  - **findAvailableSkill**：按优先级返回可用技能（大招优先，再按冷却）。  
  - **useSkill**：根据技能目标类型（单体/群体）取目标列表，对每个目标执行伤害/治疗/施加 Buff 等；伤害走 **CombatSystem.damage**，治疗走 **CombatSystem.heal**；部分技能通过 **BuffFactory** 施加 Buff（眩晕、护盾、战吼等）。  
  - 大招：怒气满可释放，可能有单独 UI（UltimateSkillUI），会暂停 BattleSystem 的 `isPaused`，播完再恢复并扣怒气。

### 4.3 Buff 系统（BuffSystem + BuffRegistry + BuffFactory）

- **BuffRegistry**（`system/BuffRegistry.js`）：配置所有 Buff（燃烧、眩晕、战吼、护盾等）的 duration、modifiers、onTick/onApply/onExpire。
- **BuffComponent**：挂在单位节点上，可挂多个，表示当前身上的 Buff 实例。
- **BuffSystem**：  
  - **addBuff**：若已有同名且不可叠加则刷新时间/护盾值；否则挂新 BuffComponent 并 init，应用 modifiers（如攻速、攻击）、onApply，更新血条/Buff 图标。  
  - **update(entity, dt)**：对每个 Buff 增加 elapsed，到 interval 触发 onTick（如燃烧扣血），到 duration 触发 onExpire 并移除；**hasStatus(entity, "stun")** 供 ActionSystem 判断是否可行动。
- **BuffFactory**：根据 Buff 名从 BuffRegistry 取配置，创建 BuffComponent 并交给 BuffSystem.addBuff。

### 4.4 伤害与战斗计算（CombatSystem）

- **CombatSystem**（`system/CombatSystem.js`）：纯逻辑，不依赖节点树。  
  - **damage(attacker, target, baseDamage, log, recorder, rand)**：  
    - 闪避判定（目标 miss）→ 暴击判定（攻击方 crit，双倍）→ 减防 → 免疫系数 → 护盾吸收 → 扣血；使用**种子随机数 rand** 以保证回放可复现。  
    - 扣血后增加目标怒气；更新血条、飘字；记录 recordDamage。  
  - **damageTrue**：无视防御/闪避/免疫，直接扣血，用于真伤技能。  
  - **heal**：治疗量不超过最大 HP，更新血条并记录 recordHeal。

### 4.5 死亡处理（DeathSystem）

- **DeathSystem**（`system/DeathSystem.js`）：  
  - **checkAndHandleDeath(entity)**：若 StatsComponent.hp ≤ 0，则记录死亡、清理 Buff/技能特效、播放死亡动画、从 **TeamRef.herosRef/monstersRef** 中移除该单位。  
  - 战斗结束条件：BattleSystem.isFinished() 为 true（一方全灭）。

### 4.6 等级与经验（LevelSystem + LevelConfig）

- **LevelConfig**：各级所需经验表。
- **LevelSystem.addExp(characterNode, expValue)**：给节点的 StatsComponent 加经验，内部若升级则按配置提升 maxHp、attack、defense、speed、crit、miss 等，并调用 **CharacterDataManager.saveCharacterLevel** 持久化。

### 4.7 道具系统（ItemSystem + ItemConfig + ItemDataManager）

- **ItemConfig**（`game/ItemConfig.js`）：道具 id、name、effectType（level_up、exp、hp、skill_scroll）、effectValue、skillId 等。
- **ItemSystem.useItem(characterNode, itemId)**：  
  - 检查拥有数量（ItemDataManager）；按 effectType 分支：  
    - **level_up**：直接升级（调用等级逻辑）。  
    - **exp**：增加经验（LevelSystem）。  
    - **hp**：恢复生命（StatsComponent）。  
    - **skill_scroll**：SkillDataManager 增加技能，并同步到节点 SkillComponent。  
  - 使用成功后 **ItemDataManager.removeItem(itemId, 1)**。
- 背包为**全局共享**，不按角色分栏。

### 4.8 战斗记录与回放

- **BattleRecorder**：  
  - **startRecording(heros, monsters)**：序列化初始状态、SelectedUnits，初始化 events 数组。  
  - 在 ActionSystem/SkillSystem/CombatSystem/DeathSystem 等处调用 **recordActionStart、recordSkillUse、recordDamage、recordHeal、recordBuffApply、recordDeath** 等。  
- **BattleReplayer**：  
  - **startReplay(battleRecord, heros, monsters, onReplayComplete)**：构建 record 中单位 ID 到当前节点的 **unitMap**，按事件时间戳推进，在对应时间执行“同类型”的逻辑（伤害、治疗、死亡、Buff 等），只做表现与状态同步，不再走 ActionSystem 的选技能/选目标。  
- 回放使用与录制相同的**种子随机数**，保证伤害/暴击/闪避一致，实现确定性回放。

## 五、数据层与适配器

### 5.1 存储模式

- **CharacterDataAdapter**、**ItemDataAdapter**、**SkillDataAdapter**、**CoinManager**（及 ServerConfig）支持：  
  - **local**：仅 localStorage（或本地 JSON）。  
  - **server**：仅 HTTP 请求。  
  - **hybrid**：先写本地再同步服务器，或先拉服务器失败再用本地。

### 5.2 主要 Manager 与 Adapter

| 数据     | Manager              | Adapter               | 说明                     |
|----------|----------------------|------------------------|--------------------------|
| 角色     | CharacterDataManager | CharacterDataAdapter  | 等级、经验、基础属性     |
| 技能     | SkillDataManager     | SkillDataAdapter      | 角色已学技能列表         |
| 背包     | ItemDataManager      | ItemDataAdapter       | 全局道具及数量           |
| 金币     | CoinManager          | （内建请求逻辑）      | 金币余额、加减、消费     |

Adapter 内部根据 **storageMode** 调用 _saveLocal/_loadAllLocal 或 _saveServer/_loadAllServer，对上层 Manager 提供统一的 async 读/写接口。

### 5.3 服务器 API 概览（server.js）

- **鉴权**：`authenticateToken` 中间件（Bearer Token），未传时可用默认 userId。
- **角色**：  
  - `GET /api/characters`（appAll）获取所有角色；  
  - `GET/PUT /api/characters/:characterName` 获取/更新单角色。
- **技能**：  
  - `GET/PUT /api/characters/:characterName/skills` 获取/更新该角色技能列表。
- **背包**：  
  - `GET/PUT /api/inventory` 获取/覆盖背包数据。
- **金币**：  
  - `GET /api/coins`、`POST /api/coins/add`、`POST /api/coins/spend`。
- **商城**：  
  - `POST /api/shop/purchase` 购买商品（扣金币、加道具）。
- **管理**：  
  - `GET /api/admin/data`、`POST /api/admin/reset` 查看/清空数据。

数据文件位于 `data/`（如 characters.json、inventory.json、coins.json、skills.json）。

## 六、配置与扩展点

### 6.1 配置类脚本（game/、system/）

- **UnitDataConfig**：英雄/怪物基础属性、技能列表；SelectScene/Battle 用其生成单位。
- **SkillConfig**：技能定义（含普通攻击、火球、治疗、眩晕、护盾、战吼等）；SkillSystem、BuffFactory 依赖。
- **BuffRegistry**：Buff 定义；BuffFactory 读取。
- **ItemConfig**：道具定义；ItemSystem、商城、背包显示使用。
- **ShopConfig**：商城商品列表（itemId、价格、分类等）。
- **LevelConfig**：等级–经验表；LevelSystem 使用。

### 6.2 组件与 Prefab

- **StatsComponent**：HP、攻击、防御、速度、暴击、闪避、免疫、怒气等；提供 `addExp`、`isDead`、`updateAttackInterval`、`updateHealthBar` 等。
- **SkillComponent**：技能列表 + 冷却时间。
- **TeamComponent**：阵营（hero/monster），供 TeamRef 与目标选取使用。
- **CombatComponent**：可选，记录 lastDamage 等用于飘字。
- **BuffComponent**：单个 Buff 实例，由 BuffSystem 挂载与移除。
- **AttackMover**：控制移动与攻击动画，与 ActionSystem 配合在 onHit 时打伤害。
- **HealthBar / RageBar / ExpBar**：与 StatsComponent 绑定显示。
- **UltimateSkillButton / UltimateSkillUI**：大招按钮与释放 UI。

新增技能：在 SkillConfig 与 UnitDataConfig 的 skills 中加入；若带 Buff，在 BuffRegistry 与 SkillSystem 的 useSkill 分支里挂上 BuffFactory。  
新增道具：在 ItemConfig 与 ShopConfig 中配置，在 ItemSystem.useItem 的 effectType 分支中实现逻辑。

## 七、小结

- **架构**：Cocos 客户端（ecs/game/system 分层）+ Node 后端，数据通过 Manager–Adapter 抽象，支持本地/服务器/混合。
- **战斗**：BattleSystem 驱动行动队列，ActionSystem 负责单次行动（Buff→技能选择→目标选择→AttackMover/技能执行→CombatSystem/DeathSystem），SkillSystem、BuffSystem、CombatSystem、DeathSystem 各司其职。
- **功能**：主菜单、选择、战斗、回放、人物查看、商城、游戏结束形成完整流程；等级、技能、道具、金币均支持持久化与服务器同步。
- **扩展**：新技能/Buff/道具/单位主要在 Config 与对应 System 中增加配置与分支即可；回放依赖事件记录与种子随机数保证可复现。

如需对某一模块做更细的“调用链”或“数据流”说明，可以指定模块名再补充。
